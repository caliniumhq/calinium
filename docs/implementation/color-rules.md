# Color Implementation Rules

## Purpose

The Color Implementation Rules define how color is applied consistently throughout every Calinium storefront.

These rules translate the Calinium Color System into predictable implementation decisions that improve usability, reinforce hierarchy, support accessibility, and maintain brand consistency.

Color should communicate meaning.

It should never exist purely for decoration.

Every color applied within Calinium should have a clearly defined purpose.

---

# Relationship to the Design System

These rules implement the principles defined in:

- Color System
- Typography System
- Spacing System
- Accessibility System
- Component System

If color implementation conflicts with the Design System, the Design System takes precedence.

---

# Core Principles

## Meaning Before Decoration

Every color must communicate a purpose.

Examples include:

- hierarchy
- interaction
- status
- emphasis
- feedback

Decorative color usage should remain minimal.

---

## Consistency

The same semantic meaning should always use the same semantic color role.

Customers should learn the interface naturally through repetition.

Avoid assigning multiple meanings to the same color.

---

## Restraint

Calinium favors neutral foundations with intentional accents.

Products—not interface colors—should attract attention.

Color should support commerce rather than compete with it.

---

## Accessibility

Every color decision must preserve readability and usability.

Color should never reduce comprehension.

Meaning must never depend solely on color.

---

## Brand Compatibility

The Color System should adapt to merchant branding without compromising usability or accessibility.

Brand colors enhance identity.

Semantic colors preserve functionality.

---

# Semantic Color Rules

Colors should always be selected by semantic role rather than visual appearance.

Examples include:

- Background
- Surface
- Primary Text
- Secondary Text
- Border
- Accent
- Success
- Warning
- Error
- Information
- Disabled
- Overlay

Components should reference semantic roles rather than fixed color values.

---

# Hierarchy Rules

Color should reinforce hierarchy rather than create it.

Hierarchy should primarily be established through:

- layout
- typography
- spacing
- imagery

Color serves as supporting emphasis.

---

# Text Rules

Primary content should always use the Primary Text color role.

Secondary information should use Secondary Text.

Muted content should remain readable.

Text should never sacrifice readability for visual style.

---

# Action Rules

Interactive elements should communicate their state consistently.

Primary actions should remain visually distinct.

Secondary actions should remain clearly identifiable.

Destructive actions should use the Error semantic role.

Disabled actions should appear inactive without becoming unreadable.

---

# Status Rules

Status colors communicate interface feedback.

Examples include:

- Success
- Warning
- Error
- Information

Status colors should remain consistent throughout the storefront.

Meaning should never rely on color alone.

Status messages should include supporting text and, where appropriate, icons.

---

# Product Rules

Color should never compete with product imagery.

Product photography defines the visual identity of the storefront.

UI colors should quietly support the purchasing experience.

Product badges should use semantic color roles rather than arbitrary brand colors.

---

# Navigation Rules

Navigation should prioritize readability.

Active navigation items should remain clearly distinguishable.

Hover and focus states should provide visual feedback without excessive decoration.

---

# Form Rules

Forms should communicate state consistently.

Examples include:

- Focus
- Success
- Error
- Disabled

Validation should remain understandable without relying solely on color.

Labels, helper text, and messages should preserve sufficient contrast.

---

# Background Rules

Background colors should establish structure.

Different background roles should communicate:

- page hierarchy
- grouping
- separation
- emphasis

Background variation should remain subtle.

Avoid excessive visual fragmentation.

---

# Border Rules

Borders should support structure rather than dominate the interface.

Borders should communicate:

- separation
- grouping
- input boundaries
- interaction states

Borders should remain visually secondary to content.

---

# Elevation Rules

Elevation should communicate hierarchy before color.

Use shadows, spacing, and layout before introducing stronger color contrast.

Color should reinforce elevation—not replace it.

---

# Responsive Rules

Color behavior should remain consistent across all devices.

Responsive layouts should never introduce different semantic meanings.

Visual consistency should be preserved regardless of screen size.

---

# Accessibility Requirements

Every color implementation must support:

- WCAG 2.2 AA contrast requirements
- Readable typography
- Visible focus indicators
- Color-independent communication
- High zoom compatibility
- System color preferences where appropriate

Accessibility is mandatory.

No color decision should reduce usability.

---

# Merchant Considerations

Merchants should customize:

- Brand colors
- Accent colors
- Theme appearance
- Color schemes

Merchants should not redefine semantic color behavior.

The system should preserve consistent meaning automatically.

---

# AI Guidelines

When generating storefronts, AI should:

- Preserve semantic color roles.
- Prioritize readability.
- Respect accessibility requirements.
- Use accent colors sparingly.
- Maintain neutral visual foundations.
- Allow product imagery to remain dominant.
- Never invent new semantic color meanings.

Color should quietly guide attention—not demand it.

---

# Quality Checklist

Before approving color implementation, verify:

## Semantics

- Colors match their semantic roles.
- No conflicting meanings exist.
- Components reuse existing semantic colors.

## Hierarchy

- Color supports hierarchy.
- Products remain visually dominant.
- Accent colors are used intentionally.

## Accessibility

- Contrast requirements are satisfied.
- Meaning is not conveyed through color alone.
- Focus indicators remain visible.

## Consistency

- Semantic colors remain consistent.
- Interactive states behave predictably.
- Status colors are reused correctly.

## Commerce

- Product imagery remains the visual focus.
- Purchase actions are clearly distinguished.
- Decorative color usage is minimized.

---

# Future Compatibility

Before introducing a new color rule, ask:

- Can an existing semantic color role solve this problem?
- Does the new rule improve usability?
- Does it preserve accessibility?
- Does it strengthen consistency?
- Will merchants understand its purpose?

If an existing semantic role already satisfies the requirement, reuse it.

The Color Implementation Rules prioritize clarity, consistency, accessibility, semantic meaning, and product-focused presentation.

Color should communicate purpose, reinforce hierarchy, and support purchasing decisions without becoming the visual center of attention.
