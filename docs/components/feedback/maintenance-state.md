# Maintenance State

## Purpose

Maintenance State communicates a planned temporary storefront-wide or feature-specific interruption with preserved brand identity and a clear return path.

It provides accurate merchant-approved context without inventing schedule, recovery time, cause, technical details, or promotional content.

## Responsibilities

Maintenance State owns planned-interruption heading, concise approved message, optional verified return time, real support or status link, minimal navigation, and localization.

Maintenance State is not responsible for unplanned error reporting, Password Page behavior, service monitoring, customer-data collection, promotional campaigns, or infrastructure disclosure.

## User Goals

Maintenance State should help customers understand that a planned interruption is occurring, what remains available, and one verified next action.

## Merchant Goals

Maintenance State should help merchants present approved interruption guidance consistently while preserving calm brand identity and avoiding unsupported promises.

## Structure

Maintenance State consists of clear heading and merchant-approved message — required.

Optional: verified expected return time, support link, status-update link, minimal navigation, real logo, and localized explanation.

## Required Elements

Every Maintenance State requires a verified planned maintenance condition, concise factual message, preserved brand identification, and an accurate available recovery or support path.

## Optional Elements

Expected return time and status link may appear only when verified and real. Support contact may appear when it is a real monitored customer route.

## Supported Variants

### Storefront Wide

Planned interruption affects the full storefront.

### Feature Specific

Only a verified service or area is temporarily unavailable while navigation continues.

### Password or Restriction Context

Uses real Shopify restriction context without redefining Password Page behavior.

### Return Time Available

Verified expected return information is shown.

## Component-Specific Rules

Maintenance State must identify planned interruption honestly, preserve real brand identity and minimal useful navigation, localize content, and distinguish a verified schedule from unknown failure.

Maintenance State must not invent completion estimate, claim scheduled maintenance for unknown cause, expose internal systems, collect unnecessary customer data, or become a promotional landing page.

## Supported States

### Active

Verified planned interruption message is shown.

### Return Time Known

Verified expected time appears with suitable qualification.

### Limited Navigation

Only real available destinations remain accessible.

### Resolved

Maintenance State is removed when the verified condition ends.

## Responsive Behaviour

Maintenance State should retain brand mark, readable localized content, minimal navigation, and touch-safe links without overflow at 320 px, zoom, and large text settings.

## Accessibility

Maintenance State must use semantic HTML, page-level heading, WCAG 2.2 AA contrast, accessible logo and links, visible focus, logical reading order, and no automatic live announcement or focus movement for static content.

## Shopify Settings

Merchants may configure approved heading, message, verified return time, real support link, real status link, logo, minimal navigation, and visibility.

The Design System controls hierarchy, exact status colors, spacing, focus, contrast, breakpoints, motion, and accessibility behavior.

## Design Tokens

Maintenance State should use maintenance-space, maintenance-heading, maintenance-text, maintenance-surface, maintenance-link, maintenance-logo, and maintenance-focus tokens.

## Motion Rules

Maintenance State should remain static and calm. No countdown animation, urgent pulse, auto-refresh animation, or decorative interruption is permitted; reduced-motion preferences are respected.

## Performance Rules

Maintenance State should server render, require no JavaScript for its message or navigation, preserve progressive enhancement, avoid heavy media and polling, use stable geometry, and remain safe through Theme Editor rerenders.

## AI Guidelines

AI should use Maintenance State only for verified planned interruption, preserve merchant-approved wording and localization, select deterministic minimal navigation, and show return time only when verified.

AI must not invent maintenance, recovery schedule, service availability, cause, support route, or promotional conversion message.

## Quality Checklist

### State

- Planned interruption is verified.
- Unknown failure uses Error Page or Alert instead.

### Recovery

- Any support or status route is real.
- Return timing is qualified and verified.

### Accessibility

- Brand, message, and navigation are semantic and readable.
- No motion or live-region interruption is unnecessary.

## Future Compatibility

Future Maintenance State refinement should remain planned-interruption-specific and Shopify-aware. New status monitoring, notification collection, or Password Page behavior requires separate implementation, privacy, and operational design.
