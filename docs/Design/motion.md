# Calinium Motion System

## Purpose

The Calinium Motion System defines how movement is used throughout every Calinium experience.

Motion is not decoration.

It is a communication tool that helps users understand change, maintain context, receive feedback, and navigate interfaces with confidence.

Every animation should have a purpose.

If motion does not improve comprehension, usability, or perceived quality, it should not exist.

---

# Design Principles

## Principle 01 — Motion Communicates Change

Motion should explain what changed.

Animations help users understand:

- what appeared
- what disappeared
- what moved
- what expanded
- what collapsed
- what became active

Movement should always reinforce understanding.

---

## Principle 02 — Motion Should Feel Natural

Movement should feel calm, intentional, and physically believable.

Acceleration and deceleration should mimic natural motion rather than mechanical transitions.

Interfaces should feel responsive—not theatrical.

---

## Principle 03 — Less Motion Creates More Meaning

When everything moves, nothing feels important.

Motion should be reserved for meaningful interactions.

Static interfaces create stronger contrast when movement is genuinely needed.

---

## Principle 04 — Consistency Builds Trust

Every interaction should behave predictably.

Animations should feel familiar across the entire platform.

Customers should never wonder how an interface will respond.

---

## Principle 05 — Performance Comes Before Animation

No animation is better than a slow animation.

Motion must never compromise responsiveness, accessibility, or page performance.

Performance is part of the experience.

---

# UX Foundations

## Doherty Threshold

Interfaces should respond quickly enough to maintain user attention.

### Application

- Immediate visual feedback after interactions.
- Loading indicators when delays are unavoidable.
- Responsive transitions that reinforce system responsiveness.

---

## Fitts's Law

Motion should support interaction rather than interfere with it.

### Application

- Buttons should remain stable during interaction.
- Avoid moving interactive targets unexpectedly.
- Never animate controls away from the user's pointer or finger.

---

## Jakob's Law

Users expect familiar motion patterns.

### Application

- Drawers slide naturally.
- Dropdowns expand predictably.
- Modals fade and scale subtly.
- Navigation behaves consistently.

Avoid surprising animations.

---

## Gestalt Principle — Common Fate

Objects moving together are perceived as related.

### Application

- Groups should animate together.
- Lists should enter consistently.
- Cards within the same collection should share motion behavior.

---

## Cognitive Load

Motion should reduce uncertainty—not create distraction.

Customers should immediately understand:

- what changed
- why it changed
- where it came from
- where it went

Animation should never require interpretation.

---

# Motion Principles

## Feedback

Every user action deserves an immediate response.

Examples:

- Button press
- Form submission
- Filter selection
- Add to cart
- Variant change

Feedback should confirm that the action was received.

---

## Continuity

Movement should preserve spatial relationships.

Objects should appear to travel logically rather than teleport.

Users should always maintain orientation.

---

## Hierarchy

Important elements may receive slightly more noticeable motion.

Supporting elements should remain subtle.

Motion should reinforce visual hierarchy.

---

## Focus

Animation should guide attention toward meaningful content.

Avoid drawing attention toward decorative interface elements.

Products remain the primary focus.

---

# Motion Categories

## Micro Interactions

Small responses to direct user actions.

Examples:

- Hover
- Focus
- Press
- Toggle
- Checkbox
- Radio button

Should feel immediate.

---

## State Transitions

Communicate interface changes.

Examples:

- Loading
- Success
- Error
- Empty state
- Disabled state

Motion should reinforce understanding.

---

## Navigation

Movement between interface regions.

Examples:

- Mobile menu
- Cart drawer
- Search drawer
- Filters
- Tabs

Navigation should preserve orientation.

---

## Layout Changes

Structural changes to page layout.

Examples:

- Accordion
- FAQ
- Expandable content
- Dynamic sections

Movement should explain the relationship between collapsed and expanded states.

---

## Emphasis

Used sparingly.

Examples:

- Newly added cart item
- Promotional announcement
- Important notification

Avoid repeated attention-seeking animations.

---

# Component Rules

## Buttons

Buttons may provide subtle feedback on:

- Hover
- Press
- Focus

Avoid excessive scaling or bouncing.

---

## Cards

Cards may elevate slightly on hover.

Motion should remain restrained.

---

## Product Gallery

Image transitions should preserve context.

Avoid abrupt image replacement.

Customers should always understand which image they are viewing.

---

## Drawers

Drawers should move from logical screen edges.

Movement should feel connected to the triggering control.

---

## Dialogs

Dialogs should enter gently.

Background content should visually recede.

Avoid dramatic zoom effects.

---

## Navigation

Menus should appear predictably.

Large navigation structures should prioritize clarity over animation.

---

# Accessibility

Motion must respect user preferences.

Interfaces should fully support:

- Reduced Motion
- Keyboard navigation
- Screen readers
- Focus visibility

Users requesting reduced motion should receive a fully functional experience with minimal or no non-essential animation.

Motion should never communicate critical information by itself.

---

# Merchant Customization

Merchants should choose an overall motion personality.

Suggested presets:

- None
- Minimal
- Balanced
- Expressive

The semantic relationships remain unchanged.

Only animation intensity changes.

---

# AI Guidelines

When generating storefronts, AI should:

- Use motion only when it improves comprehension.
- Preserve consistent interaction patterns.
- Prioritize responsiveness over visual effects.
- Reduce unnecessary animation.
- Reinforce hierarchy through subtle movement.

Motion should never become the visual focus.

Products should.

---

# Future Compatibility

Before introducing a new animation, ask:

- Does it communicate meaningful change?
- Does it improve usability?
- Does it reduce cognitive load?
- Does it reinforce hierarchy?
- Does it remain performant?
- Does it respect accessibility preferences?

If the answer is no, remove it.

The Calinium Motion System values clarity, responsiveness, and timeless interaction design over visual spectacle.

The best animation is the one users understand without noticing.
