# Calinium Iconography System

## Purpose

The Calinium Iconography System defines how icons communicate throughout every Calinium experience.

Icons are visual language.

Their purpose is to improve recognition, reduce reading effort, reinforce hierarchy, and support navigation.

Icons should clarify interfaces—not decorate them.

Every icon should communicate a single idea instantly and consistently.

---

# Design Principles

## Principle 01 — Recognition Before Interpretation

Users should recognize an icon immediately without needing to think.

Icons should represent familiar concepts using established conventions.

If users must interpret an icon, the icon has failed.

---

## Principle 02 — Simplicity Improves Comprehension

Simple icons communicate faster.

Avoid unnecessary details, decorative elements, and stylistic complexity.

Every icon should remain recognizable at small sizes.

---

## Principle 03 — Consistency Builds Confidence

Every icon should belong to the same visual family.

Stroke weight, corner treatment, proportions, perspective, and optical balance should remain consistent across the entire system.

---

## Principle 04 — Icons Support Content

Icons should never compete with typography or product imagery.

Their purpose is to reinforce meaning.

Text should remain the primary source of information whenever clarity requires it.

---

## Principle 05 — Less Is More

Not every label requires an icon.

Only introduce icons when they reduce cognitive effort or improve recognition.

Removing unnecessary icons often improves usability.

---

# UX Foundations

## Recognition Rather Than Recall

People recognize visual symbols faster than they recall textual information.

### Application

- Use familiar ecommerce icons.
- Avoid inventing custom metaphors.
- Support recognition before reading.

---

## Jakob's Law

Users expect common interface symbols.

### Application

Common examples include:

- Search
- Cart
- Account
- Wishlist
- Menu
- Close
- Chevron
- Filter
- Share

Changing these conventions increases learning effort.

---

## Miller's Law

Icons should reduce memory requirements.

Avoid introducing multiple icons that communicate nearly identical meanings.

The icon library should remain compact and purposeful.

---

## Gestalt Principle — Similarity

Icons sharing similar functions should share consistent visual characteristics.

Users naturally group similar visual elements.

Consistency improves scanning speed.

---

## Hick's Law

Too many icons increase decision time.

Interfaces should expose only the icons required for the current task.

---

## Cognitive Load

Icons should answer questions before users consciously ask them.

Customers should instantly recognize:

- Navigation
- Shopping actions
- Account actions
- Product interactions
- Status indicators

Interfaces should never require users to decode icon meanings.

---

# Icon Philosophy

Icons are supporting actors.

Products remain the main subject.

Typography provides meaning.

Icons reinforce understanding.

Motion provides feedback.

Together they create a coherent interface.

# Style Guidelines

Icons should be:

- Minimal
- Geometric
- Balanced
- Readable
- Timeless

Avoid:

- Decorative fills
- Excessive detail
- Trend-driven illustrations
- Inconsistent proportions

Calinium favors clean outline icons with optional filled variants only when required by hierarchy.

---

# Component Rules

## Buttons

Icons should support labels.

Avoid icon-only buttons unless universally recognized.

Examples:

- Close
- Search
- Menu

---

## Navigation

Navigation icons should reinforce orientation.

Avoid replacing familiar labels with unfamiliar symbols.

---

## Product Cards

Icons should remain secondary to imagery and pricing.

Product information should remain the dominant visual element.

---

## Forms

Icons should clarify inputs only when beneficial.

Avoid unnecessary decorative field icons.

---

## Status Messages

Status icons should reinforce—not replace—written communication.

Every status should remain understandable without relying solely on the icon.

---

# Accessibility

Icons must never become the only method of communication.

Critical information should also be communicated using:

- Text
- Color
- Labels
- Context

Decorative icons should be hidden from assistive technologies.

Functional icons must include accessible names.

Interactive icons require:

- Keyboard accessibility
- Visible focus states
- Adequate touch targets

---

# Merchant Customization

Merchants should not customize individual icons.

Instead, they may customize the overall icon style.

Suggested styles include:

- Outline
- Filled
- Mixed (where appropriate)

The chosen style should remain consistent across the entire storefront.

---

# AI Guidelines

When generating storefronts, AI should:

- Prefer familiar icon metaphors.
- Avoid unnecessary icons.
- Preserve visual consistency.
- Use icons only when they improve recognition.
- Never replace clear text with ambiguous symbols.

Products should remain the visual focus.

Icons should quietly support the experience.

---

# Future Compatibility

Before introducing a new icon, ask:

- Does an existing icon already communicate this idea?
- Will most users recognize it immediately?
- Does it reduce cognitive load?
- Does it improve navigation or comprehension?
- Does it remain readable at small sizes?

If not, reconsider introducing it.

The Calinium Iconography System values clarity, familiarity, consistency, and timeless design over stylistic novelty.

Great icons are understood instantly—and forgotten immediately because they simply work.
